# Phase P1 — Data + real PayPal invoices + "Start the demo" (spec, v2 after independent review)

**Goal:** the money foundation is real. All tables live; one importer; every invoice mirrored to a **real PayPal sandbox invoice** whose dates, amounts and lines equal ours; `POST /api/demo/start` gives each visitor their **own** ready copy fast. No buyer/supplier screens (P2/P3).
**Time box:** ~7 h (Mon night → Tue ~11:00 ET). **Branch:** `p1-data-mirror`. **FRs:** FR-1, FR-2, FR-12 (backend), FR-15 (link in note). **Open checks answered:** 1, 6, 8, 9 + new 10, 11 (§5).
v1 of this spec (D1–D19) is in `docs/_archive/P1-draft1.md`; an independent review (A1–A4, B1–B10, C1–C20, D1–D18, E) was resolved into this version — the "Resolves" column traces each one.

## 0. Why P1 matters for winning
Judges score Technological Implementation first (also the tiebreaker) and may only watch the video and click the link.
1. **PayPal's own invoice page looks like a real business invoice** — supplier name, bill-to "Northside Jewelers", items with SKU + memo, due dates (INV-1038 past due), the statement link in the note.
2. **"Start the demo" is fast, private and never half-built** — target ≤ 6 s, own copy per visitor, a failed start never leaves anything visible.
3. **Our numbers equal PayPal's** — any difference is visible, never silent.

## 1. Scope
**In:** tables + migration · money/date helpers · CSV importer (service only) · PayPal client · invoice functions `create/send/get/search_by_number/record_payment` · mirror service · demo seed + `POST /api/demo/start` · test database + CI Postgres · PayPal open-checks script (run early) · APIMatic proof · logging.
**Deferred to P3** (cut from P1 to fit the time box; added to the plan): `POST /api/supplier/import` endpoint, `put_adjustment`, `remind`, `seed/sample_export.csv` (generated from `build_csv(today)`, not fixed dates), any change to `/api/health/deep`.
**Not touched in P1:** the landing page and all other pages.
